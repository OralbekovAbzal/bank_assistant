# Bank Assistant

Чат-ассистент для клиентов банка на базе Gemini. Клиент входит в систему и задаёт вопросы обычным языком: «сколько у меня денег?», «на что я больше всего трачу?», «что было в сентябре?». Ассистент сам решает, какие данные ему нужны, получает их из базы через function calling и отвечает по реальным цифрам, не выдумывая их.

## Возможности

- Регистрация и вход по телефону и паролю, JWT-авторизация
- Чат с памятью: история диалога хранится в PostgreSQL и продолжается между запросами
- Ассистент отвечает на вопросы о счетах, балансе, операциях и расходах по данным из базы
- Цикл агента: модель может вызвать несколько функций подряд, с ограничением числа шагов
- Веб-интерфейс чата

## Стек

- **Python**, **FastAPI** — REST API и раздача веб-интерфейса
- **PostgreSQL** (psycopg), **Docker Compose** — пользователи, счета, транзакции, диалоги, сообщения
- **Gemini API** (Interactions API, function calling) — ответы ассистента
- **PyJWT** — авторизация, **pwdlib (Argon2)** — хеширование паролей
- **HTML + JavaScript** без фреймворков — веб-интерфейс

## Как это работает

```
Клиент → POST /chat (JWT) → FastAPI
                              │
                              ├─ user_id берётся из токена
                              ├─ диалог ищется по conv_id + user_id
                              ▼
                           Gemini ──► просит вызвать функцию (get_accounts, …)
                              ▲              │
                              │              ▼
                              └──── сервер выполняет функцию, читает PostgreSQL,
                                    отправляет результат обратно (до 5 кругов)
                              │
                              ▼
                      ответ сохраняется в messages и возвращается клиенту
```

1. Клиент отправляет сообщение в `POST /chat` с JWT-токеном.
2. Сервер берёт `user_id` из токена и находит диалог в базе.
3. Сообщение уходит в Gemini вместе с system prompt и описаниями доступных функций.
4. Если модели нужны данные, она просит вызвать функцию. Сервер выполняет её сам и отправляет результат обратно. Если после этого модели нужно что-то ещё, круг повторяется, но не больше 5 раз.
5. Gemini формулирует ответ, сервер сохраняет вопрос и ответ в `messages` и возвращает ответ клиенту.

### Функции ассистента

| Функция | Что возвращает | Параметры от модели |
|---|---|---|
| `get_accounts` | Счета клиента: номер, баланс, статус, дата открытия | — |
| `get_transactions` | Операции по всем счетам клиента, от новых к старым, с направлением (пришли / ушли) | `limit` (1–50), `date_from`, `date_to` |
| `get_spending_summary` | Расходы за период, сгруппированные по магазину или получателю, от больших к меньшим. Переводы между своими счетами не считаются расходом | `date_from`, `date_to` (по умолчанию — последний год) |

Суммы считаются в SQL (`sum`, `group by`), а не моделью: языковые модели плохо складывают числа.

### Безопасность

- **`user_id` всегда берётся из JWT и никогда не передаётся моделью.** Ни одна функция не принимает от модели «чей» запрос, поэтому получить данные другого клиента невозможно, что бы ни написал пользователь.
- **Всё, что приходит от модели, проверяется в коде:** `limit` ограничивается диапазоном 1–50, даты разбираются и проверяются, кривые значения возвращают модели понятную ошибку.
- **SQL только с параметрами** (`%s`), значения никогда не вставляются в текст запроса.
- **Ошибки функций не падают наружу:** неизвестная функция или сбой внутри неё возвращаются модели как `{"error": ...}`, без деталей реализации.
- **Цикл агента ограничен** 5 шагами, чтобы зациклившаяся модель не гоняла бесконечно платные запросы.
- **Диалог проверяется по паре `conv_id` + `user_id`:** чужой диалог возвращает 404.
- **Ассистент только читает данные:** переводов и других изменений он делать не может.
- Пароли хранятся только в виде хеша Argon2, секреты лежат в `.env`.

## Как запустить

1. Клонировать репозиторий и создать виртуальное окружение:
   ```
   git clone https://github.com/OralbekovAbzal/bank_assistant.git
   cd bank_assistant
   python -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   ```

2. Скопировать `.env.example` в `.env` и заполнить значения:
   ```
   GEMINI_API_KEY=   # ключ из Google AI Studio
   DB_PASSWORD=admin # как в docker-compose.yml
   JWT_SECRET=       # длинная случайная строка, минимум 32 символа
   ```
   Сгенерировать `JWT_SECRET`: `python -c "import secrets; print(secrets.token_hex(32))"`

3. Поднять PostgreSQL и создать таблицы:
   ```
   docker compose up -d
   Get-Content schema.sql | docker compose exec -T postgres psql -U admin -d bank_assistant
   ```
   (в bash: `docker compose exec -T postgres psql -U admin -d bank_assistant < schema.sql`)

4. Заполнить базу тестовыми данными: 5 клиентов, счета и операции за последние 90 дней.
   ```
   python seed.py
   ```

5. Запустить сервер из корня проекта:
   ```
   uvicorn app.api:app --reload
   ```

6. Открыть веб-интерфейс: **http://127.0.0.1:8000/ui/**

   Тестовый вход: телефон `+77010000001`, пароль `test1234`. У всех тестовых клиентов пароль одинаковый, телефоны с `+77010000001` по `+77010000005`.

   Документация API: http://127.0.0.1:8000/docs

### Что спросить у ассистента

- «Сколько у меня денег?»
- «На что я больше всего трачу?»
- «Покажи последние 5 операций»
- «Сколько я потратил в сентябре?»
- «Сколько у меня денег и на что я их трачу?» — здесь ассистент вызывает две функции

## API

| Метод | Путь | Описание | Авторизация |
|---|---|---|---|
| POST | `/registration` | Регистрация: `phone`, `name`, `password` | нет |
| POST | `/login` | Вход: `phone`, `password` → `access_token` | нет |
| POST | `/chat` | Сообщение ассистенту: `conv_id` (необязательно), `message` → `conv_id`, `answer` | Bearer-токен |
| GET | `/ui/` | Веб-интерфейс чата | нет |

Без `conv_id` начинается новый диалог. Чтобы продолжить его, передавай `conv_id` из ответа.

