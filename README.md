# Bank Assistant

Чат-ассистент для клиентов банка на базе Gemini. Клиент регистрируется, входит в систему и общается с ассистентом, который помнит историю диалога и отвечает на вопросы о счетах и операциях по реальным данным из базы.

## Стек

- **Python**, **FastAPI** — REST API
- **PostgreSQL** (psycopg), **Docker Compose** — пользователи, счета, транзакции, диалоги, история сообщений
- **Gemini API** (Interactions API, function calling) — ответы ассистента
- **JWT** (PyJWT) — авторизация
- **pwdlib** (Argon2) — хеширование паролей

## Что умеет

- [x] Регистрация пользователя (пароль хранится только в виде хеша)
- [x] Вход по телефону и паролю, выдача JWT-токена
- [x] Защита эндпоинтов через Bearer-токен
- [x] Чат с ассистентом, история диалога сохраняется в Postgres
- [x] Ассистент видит счета и баланс клиента (function calling)
- [x] Ассистент видит последние операции клиента
- [ ] Цикл агента: несколько вызовов функций подряд, с лимитом
- [ ] Фильтр операций по датам (`date_from` / `date_to`)
- [ ] Сводка расходов по категориям за период
- [ ] Аудит-лог вызовов функций

## Как это работает

1. Клиент отправляет сообщение в `POST /chat` с JWT-токеном.
2. Сервер берёт `user_id` из токена и находит диалог в базе.
3. Сообщение уходит в Gemini вместе с system prompt и описанием доступных функций.
4. Если модели нужны данные, она просит вызвать функцию (например, `get_accounts`). Сервер выполняет её сам и отправляет результат обратно в Gemini.
5. Gemini формулирует ответ, сервер сохраняет вопрос и ответ в `messages` и возвращает ответ клиенту.

### Безопасность

- `user_id` всегда берётся из JWT-токена и **никогда** не передаётся моделью. Модель физически не может запросить данные другого клиента, что бы ни написал пользователь.
- Параметры, которые передаёт модель (например, `limit`), ограничиваются в коде.
- Диалог проверяется по паре `conv_id` + `user_id`: чужой диалог возвращает 404.
- Ассистент только читает данные: переводов и других изменений он делать не может.

### Функции ассистента

| Функция | Что возвращает | Параметры от модели |
|---|---|---|
| `get_accounts` | Счета клиента: номер, баланс, статус, дата открытия | — |
| `get_transactions` | Последние операции по всем счетам клиента, от новых к старым | `limit` (1–50, по умолчанию 10) |

## Как запустить

1. Клонировать репозиторий и создать виртуальное окружение:
   ```
   git clone https://github.com/OralbekovAbzal/bank_assistant.git
   cd bank_assistant
   python -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   ```

2. Скопировать `.env.example` в `.env` и заполнить значения:
   ```
   GEMINI_API_KEY=
   DB_PASSWORD=
   JWT_SECRET=      # длинная случайная строка, минимум 32 символа
   ```

3. Поднять PostgreSQL и создать таблицы:
   ```
   docker compose up -d
   Get-Content schema.sql | docker compose exec -T postgres psql -U admin -d bank_assistant
   ```
   (в bash: `docker compose exec -T postgres psql -U admin -d bank_assistant < schema.sql`)

4. Запустить сервер из корня проекта:
   ```
   uvicorn app.api:app --reload
   ```
   Документация API: http://127.0.0.1:8000/docs

## API

| Метод | Путь | Описание | Авторизация |
|---|---|---|---|
| POST | `/registration` | Регистрация: `phone`, `name`, `password` | нет |
| POST | `/login` | Вход: `phone`, `password` → `access_token` | нет |
| POST | `/chat` | Сообщение ассистенту: `conv_id` (необязательно), `message` → `conv_id`, `answer` | Bearer-токен |

Без `conv_id` начинается новый диалог. Чтобы продолжить его, передавай `conv_id` из ответа.
